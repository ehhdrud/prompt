# Metaprompt

사용자의 목적을 받아 **프롬프트를 산출물로 만드는** 스킬이다. 직접 과제를 수행하지 않고, 다른 모델 인스턴스가 과제를 일관되게 수행하도록 만드는 지시문을 작성한다. 모든 판단 근거는 `references/`의 공식 가이드 요약에 둔다.

> 산출물의 역할: 메타프롬프트는 "열정적이지만 경험 없는 AI 비서"에게 주는 온보딩 문서다. 맥락 없는 동료에게 보여줘도 그대로 따라 할 수 있어야 한다.

---

## 입력

```
예시: "/metaprompt 고객 FAQ 기반 CS 챗봇 시스템 프롬프트 만들어줘"
      "/metaprompt 회의록 정리 프롬프트 바로 만들어줘"  (인터뷰 생략)
      "/metaprompt 이 프롬프트 개선해줘" (+ 기존 프롬프트 첨부)
      "/metaprompt review 스킬의 SKILL.md 프롬프트 리뷰"
      "/metaprompt codex용 리팩터링 에이전트 프롬프트"
      "/metaprompt update"  (레퍼런스를 공식 문서 기준으로 갱신)
```

| 항목 | 필수 | 설명 |
|------|------|------|
| 목적 | O | 프롬프트가 해결할 과제와 성공 기준 |
| 대상 플랫폼 | △ | Claude API / Claude Code / Codex·GPT. 미지정 시 **현재 레포 맥락**으로 추론 (`.claude/` → Claude, `.codex/` → Codex) |
| 프롬프트 유형 | △ | 시스템 프롬프트, 태스크(유저) 프롬프트, SKILL.md, 서브에이전트, CLAUDE.md/AGENTS.md, 툴 설명 |
| 기존 프롬프트 | △ | 있으면 **개선 모드**, 없으면 **신규 작성 모드** |

인자가 `update`이면 아래 워크플로우 대신 [갱신 모드](#갱신-모드)를 실행한다.

## 워크플로우

### 1. 요구사항 확정 (인터뷰)

기본은 **인터뷰 모드**다. 애매한 부분을 가정으로 메우지 말고, 아래 질문 영역이 모두 채워질 때까지 사용자에게 묻는다. 요청에 "바로", "질문 없이", "quick"이 있거나 모든 영역이 요청에 이미 들어 있을 때만 건너뛴다.

**질문 영역** (각 영역이 "확인됨" 또는 "사용자가 위임함"이 되어야 다음 단계로 간다)

| 영역 | 확인할 것 |
|------|-----------|
| 목적·성공 기준 | 무엇이 잘 된 결과인가. 실패하면 어떤 일이 생기는가 |
| 독자·사용자 | 결과물을 누가 읽는가. 그 사람의 배경 지식 수준 |
| 입력 | 형식(텍스트, 파일, 구조화 데이터), 길이, 언어, 품질(깨끗한가, 노이즈가 있는가) |
| 출력 | 형식, 길이, 톤, 언어, 표시 환경(마크다운 가능 여부) |
| 예외 처리 | 범위 밖 요청, 정보 부족, 모순된 입력일 때 원하는 행동 |
| 제약 | 금지 사항, 반드시 포함할 것, 보안·개인정보 |
| 참고 자료 | 기존 좋은 결과물이나 나쁜 결과물 예시가 있는가 |
| 실행 환경 | 대상 모델·플랫폼, 쓸 수 있는 툴, 시스템/유저 프롬프트 중 어디에 들어가는가 |
| 평가 | 어떻게 잘 됐는지 확인할 것인가 |

**진행 규칙**

1. 대화와 레포에서 확인할 수 있는 것은 묻지 않고 확인된 것으로 처리한다.
2. 한 라운드에 **2~4개**씩 묻는다. 각 질문에는 선택지와 추천 기본값을 붙여 사용자가 빠르게 고를 수 있게 한다. AskUserQuestion 툴이 있으면 그것을 쓴다.
3. 뻔한 질문은 하지 않는다. 해석이 갈리는 부분, 사용자가 아직 생각해 보지 않았을 부분을 판다.
4. 사용자가 "알아서 해"라고 한 영역은 "위임됨"으로 처리하고, 어떤 가정을 했는지 설계 메모에 반드시 적는다.
5. 모든 영역이 채워지면 확정된 요구사항을 5~10줄로 요약해 보여준 뒤 다음 단계로 간다.

**개선 모드 추가 질문**: 어떤 증상을 겪었는가(구체적 입력과 잘못된 출력), 어떤 모델에서였는가, 바꾸면 안 되는 부분은 어디인가.

### 2. 레퍼런스 로드

대상에 맞는 파일만 읽는다. 전부 읽지 않는다.

| 대상 | 읽을 파일 |
|------|-----------|
| Claude 모델용 시스템/태스크 프롬프트, 툴 설명 | [references/claude-guide.md](references/claude-guide.md) (세대 무관 원칙) + [references/claude-models.md](references/claude-models.md) (현행 모델 처방, 구식 패턴) |
| Claude Code용 CLAUDE.md, SKILL.md, 서브에이전트 | [references/claude-code-guide.md](references/claude-code-guide.md) + claude-guide.md의 §1·§4 + claude-models.md |
| Codex / GPT용 프롬프트, AGENTS.md | [references/openai-guide.md](references/openai-guide.md) |
| 모든 신규 작성 | [references/metaprompt-template.md](references/metaprompt-template.md) (설계 절차와 골격) |

양쪽 플랫폼에 동기화되는 스킬(이 레포의 `.claude/`·`.codex/` 공용)이면 claude-guide.md와 openai-guide.md의 **공통 원칙만** 사용하고, 한쪽에서만 유효한 기법(prefill, `<thinking>` 요구 등)은 넣지 않는다.

**신선도 체크**: 읽은 레퍼런스 상단의 `기준일`이 오늘로부터 **6개월 이상** 지났으면, 모델별 처방(claude-models.md, openai-guide.md §4~§6)을 적용하기 전에 해당 파일 출처의 첫 URL을 WebFetch해 대상 모델 목록과 섹션 구성이 바뀌었는지 확인한다. 바뀌었으면 사용자에게 알리고 원본 레포(prompt)에서 `/metaprompt update`를 실행하도록 권한 뒤, 이번 작업은 세대 무관 원칙 위주로 진행한다.

### 3. 설계 (신규 작성 모드)

metaprompt-template.md의 절차를 따른다.

1. **입력 변수 목록화**: 프롬프트가 실행 시 받을 가변 입력을 최소 집합으로 정한다.
2. **구조 계획**: 역할 → 맥락·동기 → 지시 → 예시 → 출력 형식 → 제약·예외 순으로 배치한다. 긴 입력(문서, 코드)은 지시보다 **앞에** 둔다.
3. **자유도 결정**: 과제가 깨지기 쉬우면 구체적 절차(저자유도), 판단이 필요하면 원칙·휴리스틱(고자유도)으로 쓴다.

### 3'. 진단 (개선 모드)

기존 프롬프트를 아래 기준으로 점검하고, **문제 → 근거(가이드 항목) → 수정안** 표를 만든 뒤 수정한다. 기존 프롬프트의 구조와 어투는 최대한 유지한다.

| 점검 항목 | 흔한 결함 |
|-----------|-----------|
| 명확성 | 모호한 동사("도와줘", "제안해줘"), 출력 형식 미지정, 성공 기준 없음 |
| 동기 부여 | 규칙만 있고 이유가 없음 → 이유를 붙여 일반화 유도 |
| 모순·중복 | 서로 충돌하는 규칙, 같은 규칙의 반복 (추론 토큰 낭비, 뒤쪽 규칙이 이김) |
| 과잉 강조 | ALL CAPS, "CRITICAL", "MUST", "If in doubt, use X", "Be THOROUGH" → 현행 모델은 과잉 트리거 |
| 부정 지시 | "~하지 마라"만 있음 → 대신 무엇을 할지로 바꾼다 |
| 구식 패턴 | prefill 의존, `<thinking>` 태그 요구, `budget_tokens`, 단계별 사고 강제, 안티 포맷팅 규칙 |
| 예시 품질 | 예시 없음 / 1개뿐 / 원치 않는 패턴 포함 / `<example>` 미구분 |
| 범위·자율성 | 언제 멈추고 언제 계속할지, 위험 동작 확인 기준이 없음 |
| 구조 | 섹션 구분 없음, 긴 자료가 지시 뒤에 있음, 변수 위치 불명확 |

### 4. 작성

- 지시문은 **명령형**으로 쓴다. 과제와 모델이 이미 아는 내용은 넣지 않는다.
- 예시는 `<example>` 태그로 감싸고, 실제 사용례와 가깝고 서로 다른 유형을 2~5개 넣는다.
- 가변 입력은 `{{VARIABLE}}` 형태로 XML 태그 안에 둔다.
- 프롬프트 본문 언어는 사용자 지정 → 기존 프롬프트 언어 → 레포 관례 → 요청 언어 순으로 따른다.
- SKILL.md나 서브에이전트 파일은 `/skill-creator`, `/subagent-creator`의 파일 형식 규칙을 따르고, 이 스킬은 **본문 품질**을 담당한다.

### 5. 자체 검토

출력 전에 아래를 확인하고, 미충족 항목은 수정한다.

```
- [ ] 맥락 없는 동료가 읽어도 따라 할 수 있는가
- [ ] 각 규칙에 이유가 있거나 자명한가
- [ ] 서로 충돌하는 지시가 없는가
- [ ] "하지 마라" 대신 "이렇게 하라"로 쓰였는가
- [ ] 출력 형식과 완료 조건이 명시되었는가
- [ ] 예시가 원하는 행동만 보여주는가
- [ ] 대상 모델에서 금지·비권장인 기법이 없는가 (claude-models.md §3, openai-guide.md §6)
- [ ] 불필요한 문장을 지워도 결과가 같다면 지웠는가
- [ ] 인터뷰에서 위임된 영역의 가정이 설계 메모에 모두 적혔는가
```

### 6. 출력

1. **완성 프롬프트**: 코드 블록으로 통째로 제시한다. 파일 대상이면 해당 경로에 바로 쓴다.
2. **설계 메모** (5~10줄): 적용한 가이드 원칙, 가정, 입력 변수, 개선 모드라면 변경 요약.
3. **검증 제안**: 프롬프트를 시험할 대표 입력 2~3개와 기대 행동. 평가 없이 "완성"이라고 하지 않는다.

## 갱신 모드

`/metaprompt update [파일명]`. 레퍼런스를 공식 문서 기준으로 다시 맞춘다. 파일명을 주면 그 파일만, 없으면 전부.

0. **원본 레포 확인**: 스킬은 원본 레포(prompt)에서 각 프로젝트로 단방향 동기화되므로 갱신은 **원본 레포에서만** 한다. `git remote get-url origin`이 `ehhdrud/prompt`를 가리키지 않으면 프로젝트 레포다. 이때는 갱신하지 않고 "원본 레포(prompt)에서 `/metaprompt update`를 실행한 뒤 sync로 받으세요"라고 안내하고 종료한다. 프로젝트에서 고친 내용은 다음 sync 때 덮어써진다.
1. **대상 결정**: `references/*.md`의 `기준일`을 읽는다. 지정 파일이 없으면 오래된 순으로 전부 처리한다.
2. **출처 조회**: 각 파일 마지막 "출처" 섹션의 URL을 WebFetch한다. 리다이렉트되면 새 URL로 다시 조회하고 출처 목록도 새 URL로 바꾼다. 404면 해당 항목을 "(접근 불가, YYYY-MM-DD)"로 표시하고 건너뛴다.
3. **차이 추출**: 원문과 현재 요약을 비교해 다음만 골라낸다.
   - 새로 생긴 권고, 삭제·철회된 권고, 바뀐 샘플 프롬프트 문구
   - 대상 모델 목록 변화 (새 세대 출시, 구 모델 비권장)
   - 새 구식 패턴 (claude-models.md §3, openai-guide.md §6에 추가)
4. **반영 원칙**:
   - 세대 무관 원칙 파일(claude-guide.md, metaprompt-template.md)은 원문이 실제로 바뀐 항목만 고친다. 표현만 다른 것은 손대지 않는다.
   - 영문 샘플 프롬프트는 원문 **그대로** 옮긴다. 의역하지 않는다.
   - 모델별 처방 파일(claude-models.md)은 "대상 모델" 줄을 갱신하고, 더 이상 서비스되지 않는 모델의 처방은 삭제한다.
   - 한국어 설명 수준과 파일 구조(목차, 섹션 번호)는 유지한다. 100줄을 넘는 파일은 목차를 맞춘다.
5. **기준일 갱신**: 변경 유무와 관계없이 조회한 파일의 `기준일`을 오늘로 바꾼다.
6. **미러링**: `.claude/skills/metaprompt/`와 `.codex/skills/metaprompt/`의 `references/`를 동일하게 맞춘다. SKILL.md의 플랫폼별 차이 줄은 유지한다.
7. **보고**: 파일별로 "변경 없음" 또는 변경 항목 목록(무엇이 어떻게)과 출처 URL을 보고한다. 커밋은 사용자가 요청할 때만 한다.

## 주의사항

- 프롬프트가 수행할 과제를 **대신 수행하지 않는다**. 산출물은 항상 프롬프트다.
- 가이드에 없는 기법을 쓸 때는 설계 메모에 "비공식" 표기를 붙인다.
- 모델별 세부 수치(effort 기본값 등)는 변동이 잦다. 숫자보다 **원칙**을 프롬프트에 담고, 수치는 설계 메모에만 적는다.
- 공식 가이드 원문이 필요하면 각 레퍼런스 하단의 출처 URL을 WebFetch로 확인한다.
