# Summary 형식 규칙

## 본문 형식

- 헤더/메타 정보(버전, 파일 수, 통계) 없이 바로 본문 시작
- `###` 제목으로 기능 단위 구분
- 각 기능 아래 `-` 글머리 기호로 변경 내용 나열
- **줄글 서술**, 코드 블록/파일 경로/라인 번호 사용 금지
- 기술 용어는 쓰되 괄호로 쉬운 설명 병기
- **명사형 종결** 사용 (예: "수정.", "삭제.", "추가.", "분리.")
- 왜 바뀌었는지(배경/문제)를 먼저, 어떻게 바뀌었는지(결과)를 뒤에 서술
- 문서/설정 파일 등 부수적 변경은 "기타" 섹션으로 모아서 간략히
- 노션에 붙여넣기 할 수 있는 톤
- 개발자가 아닌 비기술자도 대략 이해할 수 있는 수준
- 불필요한 수식어 없이 간결하게

## 출력 형식

- **반드시 코드 블록(````markdown ... ````)으로 감싸서 출력**
- 마크다운이 렌더링되지 않고 원문 그대로 복사할 수 있어야 함
