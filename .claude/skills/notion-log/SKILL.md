# Notion Log

**현재 레포**에서 **내가 작성한 커밋**을 노션 달력에 날짜·브랜치별로 기록하고, 같은 실행에서 토요일에 주간 요약까지 만든다.

> **본문 형식**: [summary 스킬의 FORMAT.md](../summary/FORMAT.md)의 "본문 형식"만 따른다 (코드 블록으로 감싸지 않음)

## 사용법

인자 없이 실행하는 것이 기본이다. 이름·레포·기간은 모두 자동으로 정한다.

| 호출 | 동작 |
|------|------|
| `/notion-log` | 기본 주간의 월~금 일일 기록 + 토요일 주간 요약 |
| `/notion-log 260226` | 해당 날짜 일일 기록만 |
| `/notion-log 260224-260226` | 범위 내 일일 기록. 범위가 월~금 한 주 전체면 주간 요약도 생성 |
| `/notion-log summary` | 기본 주간의 주간 요약만 (일일 기록 생략) |

**기본 주간**: 오늘이 월~금이면 **지난주**, 토·일이면 **이번 주**의 월~금.

날짜는 `YYMMDD` → `20YY-MM-DD`로 변환한다. "어제", "이번 주" 같은 자연어도 같은 규칙으로 해석한다.

---

## 0단계: 자동 감지 (사용자에게 묻지 않음)

| 항목 | 방법 |
|------|------|
| 레포 루트 | `git rev-parse --show-toplevel` |
| 레포 라벨 | 레포 루트 폴더명의 마지막 `-` 세그먼트 (`my-web` → `web`) |
| 작성자 | `git config user.email` |
| 노션 이름 | `notion-get-self`의 사용자 이름. 실패하면 그때만 사용자에게 질문 |

```bash
ROOT=$(git rev-parse --show-toplevel)
LABEL=$(basename "$ROOT" | rev | cut -d'-' -f1 | rev)
AUTHOR=$(git config user.email)
```

## 수집 범위 (엄격)

- **현재 레포만** 수집한다. 다른 레포 디렉토리, 다른 레포의 커밋 로그, 다른 레포 라벨의 노션 페이지는 읽지도 쓰지도 않는다.
- 대화 맥락에 다른 레포 작업이 있어도, 사용자가 다른 레포를 언급해도 대상은 실행 위치의 레포 하나뿐이다.
- 현재 디렉토리가 git 레포가 아니면 중단하고 알린다.
- 모든 git 명령은 `git -C "$ROOT"`로 실행한다.
- 커밋은 `--author="$AUTHOR"`로 **본인 커밋만** 수집한다.
- 노션 페이지는 제목이 `{LABEL}(` 또는 `{N}월 {M}주차 {LABEL}`인 것만 다룬다.

---

## 1단계: 커밋 수집

날짜별로 수집하고 브랜치별로 그룹핑한다.

1. 커밋 로그 파일 우선: `$ROOT/docs/git/commit-logs/**/YYYY-MM-DD*_{작성자명}.md`
2. 없으면 git log:

```bash
git -C "$ROOT" log --all --author="$AUTHOR" --no-merges \
  --since="YYYY-MM-DDT00:00:00" --until="YYYY-MM-DDT23:59:59" \
  --format='%h %ad %s' --date=short
```

### 브랜치 결정

- 커밋 로그 파일이 있으면 파일명 `YYYY-MM-DD[-N]_{브랜치명}_{사용자명}.md`의 브랜치명을 그대로 쓴다.
- git log만 있으면 해당 커밋을 포함하는 브랜치 중 **가장 상위 작업 라인**(release > develop > feature 순)으로 배정한다. 특정 feature/hotfix 브랜치에만 있는 커밋만 그 브랜치로 분리한다.
- 페이지 제목에는 `/`를 `-`로 바꾼 flat 형태를 쓴다 (`release/v2.1.0` → `release-v2.1.0`).

커밋이 없는 날은 페이지를 만들지 않는다.

## 2단계: 노션 달력 찾기

1. `notion-search`로 노션 이름 페이지 → 하위 인라인 데이터베이스(달력) 탐색
2. `notion-fetch`로 스키마 확인 (이름, 날짜 등)
3. 대상 기간(월~토)에 이미 있는 `{LABEL}` 페이지 조회 → 중복 확인

## 3단계: 일일 페이지 생성

날짜 × 브랜치마다 페이지 하나.

| 속성 | 값 | 예시 |
|------|-----|------|
| 이름 | `{LABEL}({브랜치})` | `web(release-v2.1.0)` |
| 날짜 | 해당 날짜 | `2026-10-06` |

본문은 해당 날짜·브랜치의 커밋만 FORMAT.md 본문 형식으로 작성한다.

## 4단계: 주간 요약 생성

해당 주 **토요일**에 페이지 하나를 만든다. 소스는 3단계 결과 + 이미 노션에 있던 같은 주 `{LABEL}(...)` 페이지다.

| 속성 | 값 | 예시 |
|------|-----|------|
| 이름 | `{N}월 {M}주차 {LABEL}` | `10월 1주차 web` |
| 날짜 | 해당 주 토요일 | `2026-10-10` |

### 취합 원칙

- **주제 기반 묶음**: 날짜순·커밋순으로 나열하지 않는다. 일자가 달라도 같은 주제면 한 섹션으로 합친다
- **결과 중심**: "무엇을 했다"가 아니라 "무엇이 달라졌다 / 무엇이 가능해졌다"
- **중복 제거**: 여러 날에 걸친 같은 작업은 최종 결과만 남긴다
- **기타**: 자잘한 수정은 마지막 "기타" 섹션으로 모은다

```markdown
## {주제 1}

- 결과 중심 bullet

## {주제 2}

- ...

## 기타

- ...
```

### 주차 계산

1. **소속 월**: 월~금 5일 중 3일 이상이 속한 달
2. **N주차**: 소속 월에 속한 주들을 순서대로 1·2·3…주차로 센다

예: 2026-09-28~10-02는 9월 소속이므로 2026-10-05~10-09가 **10월 1주차**

---

## 주의사항

- 같은 날짜·같은 제목의 페이지가 이미 있으면 덮어쓸지 확인한다. 묶어서 한 번만 묻는다
- 기간 내 커밋이 하나도 없으면 페이지를 만들지 않고 알린다
- 끝나면 생성한 페이지(날짜, 제목, 한 줄 요약)를 표로 보고한다
- 노션 MCP 도구: `notion-get-self`, `notion-search`, `notion-fetch`, `notion-create-pages`
