# 커밋 워크플로우

git diff와 git log를 분석하여 커밋 메시지 작성 및 커밋 로그 파일을 생성합니다.

> **형식 규칙**: [FORMAT.md](./FORMAT.md) 참조
> **필수 선행 검토**: [review 스킬](../review/SKILL.md) 참조

---

## 실행 모드

| 사용자 요청 | 실행 범위 |
|-------------|-----------|
| "커밋", "커밋해줘" | 1~4단계 진행 후 **push 전 사용자 확인** |
| "커밋 푸시", "커밋하고 푸시해" | 1~5단계 모두 진행 (push 포함) |
| "커밋 메시지 추천", "커밋 메시지 작성" | 커밋 메시지만 생성 (커밋 실행 안 함) |
| "커밋 로그 작성", "커밋 로그 생성" | 커밋 로그 파일만 생성 (3단계만) |

**기본 동작**: "커밋" 요청 시 4단계(commit)까지 진행 후 push 여부를 사용자에게 확인한다.

---

## 전체 워크플로우

```
0. review 스킬 실행
1. 현재 상태 파악
2. 버전 확인/결정
3. 커밋 로그 파일 생성
4. git add & commit (변경사항 + 로그 모두 포함)
5. git push
```

**커밋 로그를 커밋 전에 생성하여 하나의 커밋에 포함시킨다.**

## 0단계: 필수 리뷰

실제 커밋을 수행하는 모드에서는 먼저 [review 스킬](../review/SKILL.md)을 읽고 변경 전체에 실행한다.

- 리뷰 수정이 없고 검증을 통과하면 다음 단계로 진행한다.
- 리뷰가 동작·공개 계약·데이터 결과에 영향 없는 안전한 리팩터링만 수행했고 관련 검증을 통과하면 수정 내용을 보고하되 커밋을 계속한다.
- 제품 동작, 공개 API·타입·스키마, 데이터·상태 소유권, 인증·보안, 의존성·빌드·배포 설정에 영향이 있거나 영향도를 확신할 수 없으면 커밋을 중단한다.
- 이번 변경으로 관련 검증이 실패하면 커밋을 중단한다. 검증 도구를 실행할 수 없어도 정적 분석으로 영향도 0이 명확하면 사유를 남기고 계속할 수 있다.
- 커밋 메시지 추천이나 커밋 로그만 생성하는 모드에서도 review 결과가 있으면 이를 반영하되, review를 자동 실행하거나 코드를 수정하지 않는다.

## 1단계: 현재 상태 파악

```bash
git status
git diff --stat
git log --oneline -5
```

---

## 2단계: 버전 확인

```bash
cat VERSION 2>/dev/null
```

- **VERSION 파일이 있으면**: 해당 버전을 사용
- **VERSION 파일이 없으면**: 사용자에게 버전을 물어볼 것

> "이번 릴리즈 버전을 알려주세요. (예: 1.0.0, 1.0.1, 1.1.0)"

버전 가이드:
- **patch** (1.0.0 → 1.0.1): 버그 수정, 사소한 변경
- **minor** (1.0.0 → 1.1.0): 새 기능 추가 (하위 호환)
- **major** (1.0.0 → 2.0.0): 큰 변경, 하위 호환 깨짐

---

## 3단계: 커밋 로그 파일 생성

> **파일 위치, 파일명 형식, 로그 구조**: [FORMAT.md](./FORMAT.md) 참조

변경사항을 분석하여 로그 파일 작성:
```bash
git diff --stat
git diff --name-status
```

---

## 4단계: git add & commit

변경사항 + 커밋 로그를 모두 스테이징하여 단일 커밋으로 생성.

```bash
git add .
git commit -m "메시지"
```

- **기본**: `git add .`로 모든 변경사항(untracked 포함)을 스테이징
- 사용자가 분리 커밋을 요청한 경우에만 개별 파일을 지정하여 `git add`

> **커밋 메시지 형식**: [FORMAT.md](./FORMAT.md) 참조

---

## 5단계: push

**기본 동작**: 커밋 완료 후 사용자에게 push 여부를 확인한다.

```
✅ 커밋 완료 (Version: X.Y.Z)
push 하시겠습니까? (git push origin <branch>)
```

사용자가 처음부터 push를 요청한 경우("커밋 푸시", "커밋하고 푸시해") 확인 없이 바로 push 진행.

---

## 주의사항

- **모든 변경사항은 하나의 커밋으로 처리** (임의로 나눠서 커밋하지 않음)
- 사용자가 명시적으로 분리를 요청한 경우에만 커밋을 나눔
- **1 커밋 = 1 로그 파일** (여러 커밋을 하나로 합치지 않음)
- 이미 로그 파일이 있는 커밋은 건너뜀
