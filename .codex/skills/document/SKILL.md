# Document

현재 세션의 작업 내용을 유형별로 구조화된 문서로 정리한다.

> **형식 규칙**: [FORMAT.md](./FORMAT.md) 참조

---

## 입력

```
예시: "/document research"
      "/document plan"
      "/document task"
```

| 인자 | 필수 | 설명 |
|------|------|------|
| type | O | `research`, `plan`, `task`, `task-dev` |

### 트리거 → 타입 매핑

| 트리거 키워드 | 타입 |
|---------------|------|
| "리서치", "분석", "코드 분석", "구조 파악", "research" | `research` |
| "플랜", "계획", "설계", "plan" | `plan` |
| "작업요약", "취합", "task" | `task` |
| "개발친화적", "개발자 친화적", "개발자 관점", "task-dev", "dev task" | `task-dev` |

`task`와 `task-dev` 구분: 같은 커밋 범위를 다루되 독자 관점이 다름.
- `task`: **공유 목적**. 비개발자 포함 전체 독자 대상. 기술 용어 최소화. AS-IS/TO-BE 중심.
- `task-dev`: **개발/인수인계 목적**. 개발자 대상. 데이터 변경·영향 매핑·검증 근거·코드 참조 상세. 비개발자 요약 섹션 제거.

---

## 워크플로우

### 기본 흐름

1. **타입 결정**: 트리거 키워드 또는 인자로 타입 결정
2. **세션 분석**: 현재 대화에서 문서화 대상 내용 수집
3. **문서 생성**: FORMAT.md의 해당 타입 형식에 맞춰 작성
4. **저장**: FORMAT.md 기본 경로에 파일 생성

### Plan 타입 추가 흐름

Plan은 바로 문서를 생성하지 않고, **질문을 통해 구체화**한 뒤 작성한다.

1. **Research 확인**: 현재 세션에서 작성했거나 사용자가 명시적으로 지정한 Research 문서가 있으면 Plan 문서에서 반드시 참조 링크를 건다
2. 사용자가 작업 목표 제시
3. 목표가 모호하면 → 질문하여 명확화
4. 범위가 넓으면 → 질문하여 범위 확정
5. 확정된 내용으로 Plan 문서 생성
6. **확인 포인트 보고**: 각 단계 완료 시 해당 단계의 확인 포인트를 사용자에게 보고한다. 여러 단계를 한번에 진행한 경우 완료된 단계들의 확인 포인트를 취합하여 한번에 보고한다
7. **사후 수정 기록**: Plan 실행 후 수정이 발생하면, 해당 단계 아래에 `#### 사후 수정` 섹션을 추가하여 수정 내용과 이유를 기록한다 (FORMAT.md 선택적 섹션 참조)

### Task 타입 추가 흐름

Task는 **커밋 로그를 기반으로** 작성한다.

1. **커밋 로그 특정**: 사용자가 명시적으로 지정한 커밋 로그가 있으면 해당 로그 사용. 없으면 현재 세션의 작업 내용에서 관련 커밋 로그를 추론하여 탐색
2. **커밋 로그 분석**: 커밋 로그 파일(`docs/git/commit-logs/`)을 읽고 변경 내용 파악
3. **주제 확인**: 커밋 로그가 여러 개이고 주제가 나뉘면 사용자에게 어떤 주제로 묶을지 확인
4. **문서 생성**: 커밋 로그 내용을 AS-IS/TO-BE 관점으로 재구성하여 작성. 커밋 로그 링크는 `git remote get-url origin`으로 GitHub URL을 구성하여 절대 경로로 포함한다

### Task-dev 타입 추가 흐름

Task-dev도 **커밋 로그를 기반으로** 작성하되, 개발자 관점 상세를 우선한다.

1. Task와 동일한 1~3단계(커밋 로그 특정·분석·주제 확인) 수행
2. **세션 맥락 통합**: 커밋 로그에 없는 내용도 세션 대화에서 나온 **설계 근거·검증 방법·데이터 매핑·시행착오의 교훈**을 함께 수록
3. **문서 생성**: FORMAT.md의 `task-dev` 형식에 맞춰 작성. 코드 참조(`file:line`)와 DB SQL, 영향 매핑 표를 적극 사용. 비개발자 요약은 포함하지 않음
4. **다른 문서 참조**: 관련 Research/Plan 문서가 있으면 상단에 링크

## 주의사항

- 저장 위치는 FORMAT.md의 기본 경로를 사용한다. 기본 경로가 없는 경우에만 사용자에게 확인
- 같은 경로에 같은 파일명이 있으면 덮어쓸지 확인
- **Task는 공유 목적**으로 작성한다. 커밋 로그를 기반으로 AS-IS/TO-BE 관점에서 재구성하며, 상세 변경 내역은 커밋 로그 링크로 위임한다
- **Task vs Summary**: Task는 AS-IS/TO-BE 구조화 문서, Summary는 간단한 줄글 요약. 변경 전후를 명확히 보여줄 땐 Task, 빠르게 공유할 땐 Summary
