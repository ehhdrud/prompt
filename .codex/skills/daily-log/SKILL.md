# Daily Log

커밋 로그를 기반으로 일일 작업 내용을 노션 달력에 기록한다.

> **본문 형식**: [summary 스킬의 FORMAT.md](../summary/FORMAT.md) 참조

## 모드

| 모드 | 트리거 | 설명 |
|------|--------|------|
| daily (기본) | `/daily-log 260226 서동경` | 하루치 커밋을 브랜치별 페이지로 기록 |
| summary | `/daily-log summary 260406-260410 서동경` | 한 주(월~금) 데일리 로그를 취합해 토요일에 주간 요약 페이지 생성 |

---

## 입력

사용자 요청에서 `날짜`, `노션 이름`을 파싱한다. 레포 라벨은 자동 감지한다.

```
예시: "데일리로그 260226 서동경"
      "노션에 올려 260226 서동경"
```

| 인자 | 필수 | 설명 | 예시 |
|------|------|------|------|
| 날짜 | O | `YYMMDD` 6자리. 단일 날짜만 | `260226` |
| 노션 이름 | O | 달력이 포함된 노션 페이지 소유자 | `서동경` |

날짜는 `20YY-MM-DD`로 변환하여 사용한다. (예: `260226` → `2026-02-26`)

### 레포 라벨 자동 감지

현재 작업 디렉토리 이름에서 `-` 구분자의 마지막 세그먼트를 추출한다.

```
my-prompt     → prompt
acme-web      → web
acme-api      → api
my-project    → project
```

```bash
basename "$(pwd)" | rev | cut -d'-' -f1 | rev
```

## 워크플로우

### 1단계: 커밋 로그 수집

커밋 로그 파일에서 해당 날짜의 작업을 수집하고, 브랜치별로 그룹핑한다.

```bash
# 날짜별 커밋 로그 파일 탐색
ls docs/git/commit-logs/YYYY-MM-DD*
```

커밋 로그 파일이 없으면 git log로 대체한다.

```bash
git log --all --oneline --since="YYYY-MM-DDT00:00:00" --until="YYYY-MM-DDT23:59:59"
```

#### 브랜치명 추출

커밋 로그 파일명 형식: `YYYY-MM-DD[-N]_{브랜치명}_{사용자명}.md`

파일명의 브랜치명은 flat한 형태로 기록되어 있다. [branching 스킬](../branching/SKILL.md)의 브랜치 구조를 참조하여 원래 형태로 복원한다.

```
파일명 브랜치          →  실제 브랜치
main                   →  main
develop                →  develop
release-vX.Y.Z         →  release/vX.Y.Z
feature-vX.Y.Z-기능명  →  feature/vX.Y.Z/기능명
hotfix-이슈명          →  hotfix/이슈명
```

### 2단계: 날짜별 내용 생성

[summary FORMAT.md](../summary/FORMAT.md) 형식 규칙을 따라 날짜별로 내용을 생성한다.

**단, 출력 형식 규칙은 무시한다** — 코드 블록으로 감싸지 않고 노션 페이지 본문으로 직접 사용한다.

### 3단계: 노션 달력에 기록

1. **노션 검색**: 사용자 이름으로 페이지 검색 → 하위 인라인 데이터베이스(달력) 탐색
2. **데이터 소스 확인**: `notion-fetch`로 데이터베이스의 스키마 확인 (이름, 날짜, 태그 등)
3. **페이지 생성**: 날짜별로 페이지 생성

**페이지 속성:**

| 속성 | 값 | 예시 |
|------|-----|------|
| 이름 (title) | `{레포라벨}({브랜치명})` — **브랜치명 필수** | `web(release-vX.Y.Z)`, `prompt(main)` |
| 날짜 | 해당 날짜 | `2026-02-24` |

**브랜치별 페이지 분리**: 커밋이 여러 브랜치에 걸쳐 있으면 브랜치별로 페이지를 각각 생성한다.

예: main과 release-vX.Y.Z 양쪽에 커밋이 있으면 → `web(main)`, `web(release-vX.Y.Z)` 2개 페이지 생성

**페이지 본문**: 2단계에서 생성한 해당 브랜치의 내용만 포함

## 주의사항

- 같은 날짜에 같은 이름의 페이지가 이미 있으면 사용자에게 덮어쓸지 확인
- 노션 MCP 도구 사용: `notion-search`, `notion-fetch`, `notion-create-pages`

## Summary 모드 (주간 요약)

### 목적

한 주(월~금)의 데일리 로그를 취합하여 **주간 요약**을 생성한다. 날짜순 나열이 아닌 **주제 기반 묶음**이 핵심이다.

### 입력

```
/daily-log summary 260406-260410 서동경
```

| 인자 | 필수 | 설명 | 예시 |
|------|------|------|------|
| 날짜 범위 | O | `YYMMDD-YYMMDD` 월~금 5일 | `260406-260410` |
| 노션 이름 | O | 달력 소유자 | `서동경` |

저장 날짜는 해당 주 **토요일**로 자동 계산한다. (예: `260406-260410` → `2026-04-11`)

### 워크플로우

#### 1단계: 노션에서 주간 데일리 로그 수집

**git 로그나 로컬 파일은 읽지 않는다.** 소스는 오직 노션이다.

1. `notion-search`로 사용자 이름 페이지 → 달력 DB 탐색
2. `notion-fetch`로 날짜 범위(월~금) 내 모든 페이지 조회
3. 페이지 제목의 `{레포라벨}(...)` 부분으로 레포별 그룹핑
4. 각 페이지 본문을 읽어 변경사항 추출

#### 2단계: 레포별 주제 기반 취합

같은 레포 안에서 **주제별로 묶는다**. 시간순/커밋순 나열 금지.

취합 원칙:
- **결과 중심**: "무엇을 했다"가 아니라 "무엇이 달라졌다 / 무엇이 가능해졌다"
- **주제 응집**: 일자가 달라도 같은 주제면 하나의 섹션으로 합친다 (예: "GNB 도입" 관련 작업이 월·화·목에 걸쳐 있으면 한 묶음)
- **중복 제거**: 같은 작업이 여러 날 반복 기록되면 최종 결과만 남긴다
- **독자 기준**: 한 번 읽고 "이번 주 이 레포에 이런 변화가 있었구나"를 파악할 수 있어야 한다
- **사소한 작업 통합**: 자잘한 수정은 "기타" 섹션으로

#### 3단계: 출력 형식

```markdown
# web

## {주제 1}

- 결과 중심 bullet
- 결과 중심 bullet

## {주제 2}

- ...

---

# landing

## {주제 1}

- ...

---

# prompt

## ...
```

규칙:
- 레포별 `# {레포명}` 헤딩, 레포 간 `---` 구분선
- 레포 내부는 `## {주제}` 섹션으로 분리
- 레포 순서는 변경량이 많은 순 (web → landing → prompt 등 주요 → 부가)
- "기타" 섹션은 항상 마지막

#### 4단계: 노션에 기록

달력 DB에 페이지 생성:

| 속성 | 값 | 예시 |
|------|-----|------|
| 이름 (title) | `{N}월 {M}주차` | `4월 2주차` |
| 날짜 | 해당 주 토요일 | `2026-04-11` |

**주차 계산**:

1. **소속 월 결정** — 평일 5일(월~금) 중 **3일 이상이 속한 달**이 해당 주의 소속 월이다.
   - 예: 월·화가 3월, 수·목·금이 4월 → 4월
   - 예: 월·화·수가 3월, 목·금이 4월 → 3월
2. **N주차 결정** — 소속 월 안에서, 같은 규칙으로 소속이 정해진 주들을 순서대로 1·2·3…주차로 센다.
   - 즉, 해당 월에 "3일 이상 걸친 주"들만 후보가 되고, 그 중 몇 번째인지가 N

예시:
- 2026-03-30(월)~04-03(금): 월·화 3월, 수·목·금 4월 → **4월 1주차**
- 2026-04-06(월)~04-10(금): 전부 4월 → **4월 2주차**

페이지 본문은 3단계에서 생성한 전체 마크다운.

### 주의사항

- 같은 주차 페이지가 이미 있으면 덮어쓸지 확인
- 노션에 해당 주 데일리 로그가 하나도 없으면 에러 대신 사용자에게 알림
- 주제 분류가 모호하면 "기타"로 보내지 말고 사용자에게 질문
